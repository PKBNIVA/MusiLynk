# Security and privacy audit, October 2026

Scope: the Rails API in `backend/` at `origin/production` (7508dce): every route in `config/routes.rb` and its controller action, the models and services they use. Local only; no production system was contacted. Frontend (`src/**`) was only read, to confirm which fields it uses.

## Method

1. Read every controller and the shared concerns (authentication, ownership, permitted params, JSON serialisers, rate limits, uploads, webhooks, OAuth, export and erasure).
2. For each suspicion, wrote an integration test that fails on the audited code (`backend/test/integration/security_audit_2026_10_test.rb`). Suspicions whose test passed were dropped as not findings.
3. Fixed each confirmed finding minimally; the same test turns green.
4. Regression guard added: every `/api/admin/*` route answers 401/403 to anonymous, jobseeker and employer callers, and 403 to an admin token sent from the wrong origin when `ADMIN_ORIGIN` is set.

Independent check: the audit session could not spawn a second agent, so an independent reviewer examined PR #151 afterwards. It did not approve the first round and found the gaps listed under "Review round 1" below; those are fixed, each with a test that failed first (`security_review_2026_10_test.rb`).

## Areas checked and found sound

Ownership scoping (applications, conversations, messages, bookings, payments, invoices, uploads, resumes, portfolios, acts, notifications, saved searches/job alerts, reports, urgent requests, talent folders) uses `current_user.<assoc>.find` or explicit party checks. Profile, act, job and portfolio params are allow-listed (no role/status/verified/plan/owner). Public payloads use allow-lists (`PUBLIC_PROFILE_KEYS`, `Job::PUBLIC_COLUMNS`). Razorpay webhook verifies HMAC with constant-time compare and is idempotent; Brevo webhook needs a secret. Google OAuth state is signed with PKCE and `return_to` is path-only and prefixed with the frontend origin (no open redirect). Uploads check type, size and magic bytes and are owner-scoped. Sessions slide, are capped, are revoked on password reset/change, email change and suspension. Logs filter tokens, passwords, codes and message bodies. SQL uses bound parameters. CORS excludes the admin API from public origins.

## Review round 1

An independent reviewer did not approve the first push. Items, all fixed with a failing-first test in `backend/test/integration/security_review_2026_10_test.rb`:

| Id | Sev | Issue | Fix |
|----|-----|-------|-----|
| REV-1 | P1 | `POST /api/auth/reset-password` signed an admin in with no second factor; forgot-password mailed admins under the admin lock. | Admins get no session from a reset (`signInRequired: true`); no reset token or mail for admins while `ADMIN_ORIGIN` is set. |
| REV-2 | P1 | An attacker's pre-linked Google identity (or verified phone) survived the owner proving the mailbox. | `reclaim_unverified_credentials!` also destroys auth connections and clears phone; Google callback reclaims first when an unverified owner's link carries a different email. |
| REV-3 | decision | Dropping the pre-verification password locks out honest sign-ups. | Kept (an attacker's password must not survive), made humane: the owner gets the `account_password_removed` notice and login answers `USE_EMAIL_CODE`. The reviewer's test now asserts this instead of the opposite. |
| REV-4 | P2 | Editing a post without naming `visibility` or `genres` reset them (a followers-only post became public). | Update changes only the keys present. |
| REV-5 | P2 | portfolio_share / job_share previews embedded items made private, closed jobs and internal columns. | Previews show only currently public items / published jobs, with public-view fields. |
| REV-6 | P1 | AI top-up with `Idempotency-Key` returned 500; production without Razorpay keys fell through to the free mock credit; an empty `RAZORPAY_KEY_SECRET` made forgeable signatures. | 500 fixed; both paths fail closed (503). |
| REV-7 | P2 | Erasing a voucher deleted joined/verified vouches (the vouchee's evidence). | Only unanswered invitations are deleted. |
| REV-8 | note | Export with a connected Google account works and omits tokens. | Test only, passed. |
| WH-1 | P2 | Razorpay webhook dedupe used the unsigned `X-Razorpay-Event-Id` header, so a replayed header dropped a different signed event. | Keyed on a digest of the signed body. |

Note on the reviewer's REV-2 test: once the pre-linked identity is destroyed, that Google account is simply a stranger and signs up as a new user (not an error). The test now asserts what matters: it can never sign in to the victim's account, and the victim's connections and phone are gone.

### Owner decisions, now decided

| Item | Decision | Status |
|------|----------|--------|
| Verification-link pre-hijack | Password sign-in is refused (403 `EMAIL_VERIFICATION_REQUIRED`) until the email is verified; `POST /api/auth/resend-verification {email}` resends (same answer for every address). Admins and synthetic QA accounts exempt. | Done (frontend must show the code and offer resend) |
| Google login CSRF | `state` is bound to a signed, HttpOnly, Secure, SameSite=Lax cookie (`verse_oauth_state`, path `/auth/google`) set by `/start` and checked by `/callback`. Backend only. | Done |
| Enumeration codes (409 on register, `USE_EMAIL_CODE` / `USE_CONNECTED_SIGN_IN` on login) | Accepted: the sign-in UI depends on them. Login reveals them only for passwordless accounts. | Accepted risk |
| `candidateEmail` in the hirer applicants list | Removed from the payload. `src/app/pages/EmployerApplications.tsx` (and `apiTypes.ts`) still read it behind `a.candidateEmail &&`, so the email link silently disappears: for the UI sweep. | Done, UI follow-up |
| Workspace `tax_id` / `billing_email` | Owners and admins only. Frontend does not read them. | Done |
| Booking payments endpoint | Returns only id, booking id, kind, currency, status, amount, timestamps, fee fields and invoice id. | Done |
| Jobs of deleted accounts | `GET /api/jobs/:id` is 404 for them (admins excepted). | Done |
| Audit logs on erasure | Emails and network addresses in the user's entries are replaced with `[erased]`; the entries stay. | Done |
| `job_share` | Only the poster's own published listing. | Done |
| `founder_notes` in the export | Stay out (moderators' notes, not the person's data). | Documented |
